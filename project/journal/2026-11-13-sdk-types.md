# SDK defines its types (SHARD-AUTHORING SA12)

- `sdk-no-facade` 33 -> 0; `lint/ratchet.json` drops the rule's entry, so any new
  facade fails lint (checked with a throwaway probe file).
- Author data types are now the SDK's own: clip rows, the bake row, the
  phased and roaming boss rows (and their nested rows), the species row and
  its brain (brain data from shard-format's schemas), `BowStyle`,
  `ViewmodelFeel`, `MeleeProfile`. `MeleeProfile` leaves out engine's
  `pickup` (a runtime factory); its icon, touch and slot keys still come from
  engine's declaration-merged host maps.
- `test/sdk-engine-types.test.ts` (tsc via tsconfig.author.json) keeps each
  equal to engine's. Proved red: a scratch copy of engine's bakedGeometry
  with `indexCount: number | null` fails it; the real one passes.
- The bake codec (`BAKED_BYTES`, `pad4`, `bakedGeometryBytes`,
  `readBakedGeometry`) is real SDK code now, with a parity test against
  engine's reader (f32, f16, i8 positions, u16/u32/no index).
- Deleted runtime-only aliases nobody imports: `ClipCtx`, `playClips`,
  `clipAnimate`, `appendGeometry`, `PhasedBoss{Ports,Fight,Body,State}`,
  `RoamingBossFight`, the `SpeciesBrains` type. `phasedBossFight` and
  `speciesBrains` still forward to engine (SA26's real-helper work).
