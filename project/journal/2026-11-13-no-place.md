# 2026-11-13: `upload --no-place` and the grid line (SA32)

> Written by: Claude

Meta SHARD-AUTHORING SA32 (J314 Q13: "proofs skip placing").
`wildshard upload --no-place` sends `place: false` in the commit body;
without it no `place` field goes, as before (the API places by
default). After the `committed:` line upload prints api-server SA30's
`placement` as one line, then the `/slug/<slug>` link on each channel
the upload moved (staging: preview and staging; prod: all three; a
DEL7 revival: preview), each marked `(page not built yet)` because the
page is SA36 and SA37's. Printing the links now, marked, was picked
over printing nothing: the shape is fixed by the plan, and the mark
says plainly the page is not there.

The answers: `placed at (0,3) on preview, staging` (plus `; not on
staging's grid` for a moved channel the API could not add),
`grid full, not placed`, `not placed (--no-place)` on a first upload,
`grid left as it was (--no-place)` later (a held cell stays, and a
prod upload adds no production cell), and a failed grid step says to
run the same upload again. Live, `GRID_AUTOPLACE` is off and the API
sends no `placement`; that, and a past-first upload of a shard with no
cell, print `no new cell: ...` naming both, since the CLI can't tell
which.

`placement` and `revived` parse as `unknown` in the commit answer and
are checked in `placement.ts` (review MUST): the row is recorded by
then, so a shape the CLI can't read prints a line and the upload still
succeeds. The double's `grid` state plays the API's grid step.
