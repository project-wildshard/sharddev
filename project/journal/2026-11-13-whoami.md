# 2026-11-13: whoami asks which account (DEL6's gap)

> Written by: Claude

Meta SHARD-DELETE DEL6 says `wildshard whoami` prints the email; it
printed only the key's source and first characters, since api-server
had no route that names a key's account. api-server v0.12.0
(`a125d27`) adds `GET /api/accounts/me`.

- `whoami` reports the key line first, then asks the server (`--server`,
  else `WILDSHARD_API_URL`) and prints `account <email> owns N slugs
  (and M deleted)`. No server: it says so. A 404 (not api-server, or
  older than v0.12.0) keeps the key line only; a 401 says the server
  does not know this key and exits 3. 15 s timeout; the key goes only
  to https or localhost and is never printed whole.
- `auth-double.ts` answers the route: the double's own key a fixed
  account, a key `POST /api/accounts` made its email and no slugs,
  another key 401, `accounts.me = undefined` the older API's 404.

Built on `plan/whoami` by opus-whoami while opus-del10 held `main.ts`
and `command.ts` dirty on main; it lands after DEL10 (both touch those
two files: keep DEL10's delete wiring and take this whoami line).
