# 2026-11-14: sharddev on shard-format 0.5.3 and engine 0.1.19

Meta SHARD-SOURCE SS3 needed an sdk on format 0.5.2 or later
(Brasscap's look rides 0.5's render hosts), and npm's newest sdk,
0.2.13, still pinned format 0.4.10. The coordinator's rule is that
releases never wait (J327, J331), so this lane moved the pins and
released the sdk itself.

- Format 0.5 renamed its modules. sharddev follows by path and import
  alias only, so call sites keep their names: `product` to
  `shardfileAssets`, `productValidation` to `shardfileValidation`
  (`validateShardfileProduct` to `validateShardfileFolder`,
  `ProductFiles` to `ShardfileFiles`, `admitShardfileProduct` to
  `admitShardfileFolder`, `assertProductTargets` to
  `assertShardfileTargets`, `ValidatedProduct` to
  `ValidatedShardfile`), `productAudio` to `shardfileAudio` and
  `directorProduct` to `directorDocument`.
- Engine 0.1.18 can't run on format 0.5: its client and server import
  `@wildshard/format/product` and two `validationReceipt` names that
  0.5 dropped. So the engine pin moves to 0.1.19 (on `^0.5.2`) in the
  same commit.
- Not taken: `plan/mossrender`'s own 0.5.2 bump and its Template look
  work. They are another lane's and still unlanded; this commit did
  the same renames from the 0.5.3 export list.
