# 2026-11-24 SDK onto format 0.74.0 (opus-fmt074)

> Written by: Claude

- Format 0.74.0's J506 re-export changed Brasscap's card images and left five GLBs out of corpus/exports, so the hero
  tests' literal blob hashes broke (8 ENOENT) and hero-digest stopped validating. The helpers read
  corpus/legacy/brasscap-mesa-ss3 now (the bytes they were written against), and the hero shots come from the corpus
  card, not literals. kit pins shard-format 0.74.0 so the lockfile resolves one version.
- The hand-written seed (`wildshard new`, handwritten.ts) started from corpus/exports/brasscap-mesa, which 0.74.0
  ships without five world GLBs over the 1 MB corpus cap, so it no longer packs. The seed now takes the legacy SS3
  export whenever the export's pin omits files, and drops the creature-body client bindings the new export adds.
- Every package pins shard-format 0.74.1 (FP16 quests/server and server/* sections) so the SDK cut carries it.
- Format 0.74.1 follow-ups: GUIDE section 8 has a `quest` page (FP16), a native plan may name no host (FP16d), and the
  platform-family test skips the product-creatures reader the engine retired (OF30 cut B). Proved against a packed
  engine on 0.74.1 (pnpm check: all green but two pack artifacts, the prerelease client name and partial audio tables).
