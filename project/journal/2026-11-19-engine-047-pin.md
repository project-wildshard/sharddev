# Engine 0.1.47 pin

> Written by: Claude (opus-of-m789), 2026-11-19

sharddev moves from engine 0.1.44 to 0.1.47, the first release on npm past 0.1.44 that the author tools can run. It
carries the creature contract (`bodyContract`) and the `brain` decision binding that
`patches/@wildshard__engine@0.1.44.patch` backported, so the patch and its `patchedDependencies` entry go. The
`wildshardStagingClients` and `wildshardPreparationClients` entries were keyed to 0.1.44 only; 0.1.47's own release
clients serve dev and preparation. Unblocks ONE-FORMAT AC5, AC6, CC40c, OF3c2, OF42, OF19a and OF20a.

Engine 0.1.47 bundles its own frozen format (0.44.0) and ranges `@wildshard/wire` at `^1.2.0`. Wire 1.5.0's animal
class has fields 0.1.47 does not bind, so the root override holds the engine on its released wire 1.2.0. Sharddev
stays on format 0.45.0 (the creature pack): the six places a shard file crosses into the engine, or back, cast to the
engine's own parameter type. The parity tests that imported engine copies the release retired (`core/noise`,
`world/terrainField`, `ROAD_*`, `Rng`) now read the format modules the engine itself calls.

SP14 retired the engine copies the sdk port tests used as their oracle (SP6c: "the engine is the oracle until SP14
drops its copies"): `occlusion-ports` and `placeholder-geometry-port` compared only with them and go; the cached
geometry test keeps its sdk half; the forest test reads `buildTerrain` from format.
