# The SDK on format 0.79, and the seed it now keeps itself

> Written by: Claude (lane opus-nalati), 2026-11-25

Meta QA 11-24 row 70 wants Nalati to drop its grass card clumps, which
only format 0.79 lets a shard leave out. No SDK carried 0.79: every
release through 0.5.1 pinned 0.78.0. Moving the pins was a one-line
change that typechecked, and then 29 tests and `wildshard new` broke.

Format 0.79.0 deleted `corpus/legacy/brasscap-mesa-ss3` (ZONE-SNAPSHOTS
ZS5, J507). The hand-written seed fell back to it because the current
Brasscap export leaves out five GLBs over its 1 MB cap: the terrain
tiles and props, so it is no whole shard file. `new --template blender`
then refused with "missing file: blobs/glb/00bc05c8…".

The SDK now ships its own seed, `packages/sdk/seed/brasscap-mesa`:
format 0.78.0's legacy copy carried to 0.1.0.6 by format 0.79.2's own
`migrateShardfile` (15 steps, from 0.1), with its build receipt
`validation.json` kept as it was. It packs on 0.79.2. The dev and
upload test helpers read that seed, the one an author gets, instead of
a folder inside format. The Nine Dragon manifest fixture loses
`gridShardfile`, which 0.79 deleted.

When the format moves again, migrate the seed again; the pin file
beside it says from what and with which format.
